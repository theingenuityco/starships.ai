# Migration Test Scenarios Guide

This guide covers the comprehensive test suite for the MCP Connector Instance Migration (Phase 1, Task 1.3).

## Overview

The migration test suite validates the transformation from the old architecture:

```
Starship ──HAS_CONNECTOR──> MCPServerOption (Shared Template)
```

To the new instance-based architecture:

```
Starship ──HAS_CONNECTOR_INSTANCE──> MCPServerConnector ──CREATED_FROM──> MCPServerOption
```

## Test Scenarios

### 1. Empty Database Migration

**Objective**: Validate migration process on empty database
**Expected Result**:

- Migration completes successfully
- 0 relationships migrated
- No errors or data corruption

### 2. Single Starship Migration

**Objective**: Test basic migration functionality
**Setup**: 1 starship with 2 connectors
**Expected Result**:

- 2 connector instances created
- All relationships properly established
- Original HAS_CONNECTOR relationships removed

### 3. Large Dataset Migration

**Objective**: Test performance and scalability
**Setup**: 100 starships with 500 total connectors
**Expected Result**:

- All 500 relationships migrated correctly
- Performance benchmarks met:
  - Migration time: <1 second per 100 relationships
  - Memory usage: <100MB for 10,000 relationships
  - Database locks: <5 seconds total lock time

### 4. Concurrent Access During Migration

**Objective**: Validate transaction isolation
**Setup**: Migration running with concurrent read/write attempts
**Expected Result**:

- Migration completes successfully
- Concurrent operations are properly blocked or handled
- No data corruption occurs

### 5. Rollback After Partial Migration

**Objective**: Test rollback functionality
**Setup**: Force migration failure at 50% completion
**Expected Result**:

- Rollback restores original state
- No orphaned connector instances remain
- All original relationships restored

## Running Tests

### Prerequisites

1. **Neo4j Database**: Ensure Neo4j is running and accessible
2. **Environment Variables**: Set up database connection:
   ```bash
   export NEO4J_URI="[NEO4J-LOCAL-URL]"
   export NEO4J_USERNAME="neo4j"
   export NEO4J_PASSWORD="your-[DEFAULT-PASSWORD]"
   ```

### Test Commands

```bash
# Run all migration test scenarios
npm run test:migration

# Run individual scenarios
npm run test:migration:empty        # Empty database test
npm run test:migration:single       # Single starship test
npm run test:migration:large        # Large dataset test
npm run test:migration:concurrent   # Concurrent access test
npm run test:migration:rollback     # Rollback test
```

### Test Environment Setup

The test suite automatically:

1. Creates isolated test data with `test-` prefixes
2. Cleans up all test data after each scenario
3. Validates database state before and after migration
4. Measures performance metrics

## Troubleshooting

### Common Issues

1. **Database Connection Failed**
   - Verify Neo4j is running
   - Check connection credentials
   - Ensure database is accessible

2. **Test Data Cleanup Issues**
   - Manually clean test data: `MATCH (n) WHERE n.id STARTS WITH 'test-' DETACH DELETE n`
   - Restart Neo4j if needed

3. **Performance Benchmark Failures**
   - Check system resources
   - Verify database performance
   - Consider adjusting benchmark thresholds for development environments

4. **Migration Validation Errors**
   - Review migration logic in `001-connector-instances.ts`
   - Check for data consistency issues
   - Verify relationship creation queries

### Debug Mode

For detailed debugging, modify the test scripts to include additional logging:

```typescript
// In test-migration-scenarios.ts
console.log('[DEBUG] Pre-migration state:', preState);
console.log('[DEBUG] Migration result:', migrationResult);
console.log('[DEBUG] Post-migration state:', postState);
```
