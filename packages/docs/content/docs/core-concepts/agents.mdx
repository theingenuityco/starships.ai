# Agents

The foundational framework for creating AI assistants that understand context, use tools, and execute complex workflows autonomously.

<Callout type="success">
  **Framework Core**: Agents are the building blocks of your AI workforce - each one a specialized assistant built on the same universal architecture.
</Callout>

## What Are Agents?

**Agents** are AI entities that combine language understanding with tool usage and memory retention. Unlike simple chatbots, agents can:

- **Take Actions**: Use tools to interact with systems, APIs, and data
- **Remember Context**: Maintain conversation history and learned preferences
- **Execute Workflows**: Follow multi-step processes with decision making
- **Collaborate**: Work with humans and other agents on complex tasks

Think of agents as **AI teammates** that understand your domain and can work independently within defined boundaries.

## Universal Agent Architecture

Every agent in the Starships.ai framework shares the same core architecture:

## Core Components

- **🧠 Personality**: System prompt defining expertise, communication style, and behavioral guidelines
- **🛠️ Tools**: Set of capabilities like API calls, data processing, file operations, integrations  
- **💾 Memory**: Persistent context including conversation history, user preferences, and learned patterns
- **📋 Blueprints**: Workflow definitions that specify how the agent executes multi-step tasks
- **⚙️ Configuration**: Model selection, permissions, timeout settings, and operational parameters

## The Universal Agent Blueprint

Every agent follows the same core execution pattern:

```mermaid
graph TD
    START([start]) --> LLM[llm: AI Processing]
    LLM --> CHECK{conditional: Has Tool Calls?}
    
    CHECK -->|No Tool Calls| END([end: Return Response])
    CHECK -->|Has Tool Calls| ARGS[code: Prepare Arguments]
    
    ARGS --> TOOL[tool: Execute Function]
    TOOL --> RESULT[mutate: Add Tool Result]
    RESULT --> LLM
    
    style START fill:#22c55e
    style END fill:#22c55e
    style LLM fill:#3b82f6
    style CHECK fill:#f59e0b
    style ARGS fill:#8b5cf6
    style TOOL fill:#10b981
    style RESULT fill:#06b6d4
```

### How Each Node Works

- <span style={{color: '#0066cc'}}>**[start](/core-concepts/blueprints#start-node)** 🔗</span>: Receives input and triggers agent execution
- <span style={{color: '#0066cc'}}>**[llm](/core-concepts/blueprints#llm-node)** 🔗</span>: Processes requests using AI models, decides on tool usage  
- <span style={{color: '#0066cc'}}>**[conditional](/core-concepts/blueprints#conditional-node)** 🔗</span>: Routes execution based on LLM decisions (tools vs. response)
- <span style={{color: '#0066cc'}}>**[code](/core-concepts/blueprints#code-node)** 🔗</span>: Prepares data and formats tool arguments for execution
- <span style={{color: '#0066cc'}}>**[tool](/core-concepts/blueprints#tool-node)** 🔗</span>: Executes capabilities like API calls, data processing
- <span style={{color: '#0066cc'}}>**[mutate](/core-concepts/blueprints#mutate-node)** 🔗</span>: Updates memory with tool results for next LLM cycle
- <span style={{color: '#0066cc'}}>**[end](/core-concepts/blueprints#end-node)** 🔗</span>: Returns response when agent has complete answer

### The Intelligence Loop

This universal pattern enables agents to:
- **Analyze** requests against available capabilities
- **Gather** additional data through tool execution  
- **Synthesize** information into helpful responses
- **Remember** context for future interactions

## Memory Architecture

**Conversation Memory** (`state.messages`):
- Remembers what you've discussed
- Maintains context across interactions
- Learns your preferences over time

**Tool Memory** (`state.tools`):
- Knows what capabilities are available
- Remembers successful tool combinations
- Adapts to new tools automatically

**Custom Memory** (`state.*`):
- Stores workflow-specific data
- Maintains progress on multi-step tasks
- Keeps track of user preferences and settings

### Memory in Action
When you ask "Continue where we left off," the agent knows:
- What you were working on
- Which tools were being used
- What decisions were made
- What still needs to be completed

**Shared Memory** (between agents):
- Team context and coordination
- Cross-agent workflow results  
- Organizational knowledge base

## How Agents Process Requests

### The Tool-Calling Loop
What makes agents intelligent rather than just chatbots:

<Steps>
<Step icon="🧠">
### LLM Analyzes Request
The AI model examines your input and compares it against available tools and conversation history
</Step>

<Step icon="🤔">
### Decides on Action
Either provides a direct response or identifies which tools are needed to gather more information
</Step>

<Step icon="🔧">
### Executes Tools
Calls external APIs, searches databases, processes files, or performs calculations as needed
</Step>

<Step icon="🔄">
### Incorporates Results
Adds tool results to its understanding and repeats until it can provide a complete answer
</Step>
</Steps>

**Example Flow**:
```
User: "What's our team's progress this week?"

Agent thinks: "I need project data" → Calls project-status tool
Tool returns: Current task completion rates
Agent thinks: "I need recent updates" → Calls team-activity tool  
Tool returns: This week's commits and updates
Agent responds: "Your team completed 12 tasks this week, 3 ahead of schedule..."
```

### Why This Works
- **Self-contained**: Each agent has AI model + tools + memory
- **Purpose-built**: Same architecture, different tools = different capabilities  
- **Composable**: Agents can work together on complex workflows
- **Learning**: Every interaction improves decision-making

## Common Agent Patterns

## Advanced Framework Concepts

### Agent Collaboration
**Multi-Agent Workflows**: Agents can coordinate on complex tasks
- **Handoffs**: Pass work between specialized agents
- **Parallel Processing**: Multiple agents work simultaneously  
- **Shared Context**: Collaborate using shared memory and context

### Dynamic Capability Expansion
**Runtime Tool Addition**: Agents can gain new capabilities without rebuilding
- **Hot Tool Loading**: Add tools to running agents
- **Capability Discovery**: Agents learn about new available tools
- **Permission Management**: Control what tools agents can access

### Enterprise Integration
**Framework Extensibility**: Connect agents to any system
- **Custom Tool Development**: Build domain-specific capabilities
- **API Integration**: Connect to existing business systems
- **Security Framework**: Role-based access and audit trails

## Performance and Monitoring

### Agent Analytics
**Built-in Monitoring**: Track agent performance and usage
- **Response Times**: Monitor speed and efficiency
- **Success Rates**: Track task completion and accuracy
- **User Satisfaction**: Collect feedback and ratings
- **Cost Tracking**: Monitor API usage and resource consumption

### Optimization Strategies
**Continuous Improvement**: Enhance agent performance over time
- **Workflow Optimization**: Improve blueprint efficiency
- **Tool Selection**: Choose optimal tools for each task
- **Model Tuning**: Select appropriate AI models for different needs
- **Memory Management**: Optimize context and memory usage
